# 架构设计文档

## 1. 系统概述
PHP 服务管理面板是一个轻量级的管理系统，旨在提供容器化环境下的服务监控与控制模拟。系统采用经典的三层架构，并完全运行在 Docker 编排的环境中。

## 2. 总体架构
系统由以下四个主要组件构成：
1.  **Web 代理层 (Nginx)**: 负责静态资源分发及请求路由，作为系统的统一入口。
2.  **应用逻辑层 (PHP-FPM)**: 处理业务逻辑、日志记录及与数据库的交互。
3.  **持久化层 (MySQL)**: 存储服务状态、描述信息及操作审计日志。
4.  **宿主机映射层 (Volumes)**: 确保数据库数据和系统日志在容器重启后不丢失。

## 3. 网络架构
所有容器运行在自定义的 Docker 网络 `service-network` 中：
- `web` 容器通过端口 `80` 提供对外服务。
- `web` 容器内部通过服务名 `php:9000` 与应用层通信。
- `php` 容器通过服务名 `db:3306` 与数据库连接。

## 4. 日志架构
- **Nginx 日志**: 映射至 `./LOG/nginx`。
- **业务日志**: PHP 应用写入 `/panel/LOG/app.log`，通过项目根目录挂载实时同步至宿主机的 `./LOG` 目录；代码层面强制日志路径必须位于 `LOG/` 之内，越界路径自动回退。
- **数据库日志**: MySQL 的持久化存储位于 `./data`（约束：数据库文件必须放在 `data/` 下）。

## 5. 目录结构自检
- 页面打开时，前端先调用 `api.php?action=selfcheck`，检查 `www`、`data`、`LOG` 三个目录是否存在且可写，并校验“数据库在 data 下、日志在 LOG 下”两条路径约束。
- 自检未通过时，页面只展示失败项与修复建议（如 `mkdir -p` / `chmod` 命令），不渲染任何业务按钮；同时 `list`/`toggle` 等接口在服务端返回 HTTP 503 拒绝服务，避免前端出现一堆不可用按钮。
- 自检通过后才会加载服务列表与操作按钮。
