# 用户手册

## 1. 快速开始
1.  **环境准备**: 确保您的计算机已安装 Docker 和 Docker Compose。
2.  **获取项目**: 进入项目根目录。
3.  **启动系统**:
    ```bash
    docker compose up -d
    ```
4.  **访问页面**: 打开浏览器访问 `http://localhost:8080`。

## 2. 界面操作说明
- **服务看板**: 展示了系统检测到的所有服务。
- **状态标签**: “运行中”表示服务正常，“已停止”表示服务处于关闭状态。
- **操作按钮**:
  - 点击 **[启动]**：激活对应服务条目。
  - 点击 **[停止]**：禁用对应服务条目（颜色将变为灰色）。
- **刷新按钮**: 页面右上角可手动拉取最新状态。

## 3. 目录结构自检
页面打开时会先进行目录结构自检，通过后才加载服务功能：
- **检查项**: `www`、`data`、`LOG` 三个目录必须**存在且可写**；数据库文件必须放在 `data/` 下，日志只能写进 `LOG/`。
- **自检失败时**: 页面只显示失败原因与修复建议（如 `mkdir -p <路径> && chmod 775 <路径>`），不会显示服务列表和操作按钮。按提示在服务器上修复后，点击页面上的 **[重新自检]** 即可。
- **接口表现**: 自检未通过期间，后端接口统一返回 HTTP 503，操作不会被静默执行。

## 4. 查看日志
您可以随时在项目的 `LOG` 文件夹下查看日志记录：
- `app.log`: 记录了所有的用户操作（谁在什么时候启动/停止了什么服务）。
- `nginx/access.log`: 记录了 Web 访问详情。

## 5. 常见问题 (FAQ)
- **Q: 页面显示“数据库连接失败”？**
  - A: 首次启动时，MySQL 容器可能还没完全就绪。请等待约 10-20 秒后刷新页面即可。
- **Q: 页面提示“目录结构自检未通过”？**
  - A: 按页面给出的建议命令修复即可。例如缺少 `LOG` 目录时执行 `mkdir -p LOG && chmod 775 LOG`；目录不可写时执行 `chmod 775 <目录>` 或将目录属主调整为 Web 运行用户。
- **Q: Docker 部署时自检提示 `data` 目录不可写？**
  - A: MySQL 容器会把 `data` 属主改为 mysql 用户，导致 PHP 容器判定不可写。可在宿主机执行 `chmod -R o+w data` 后点击“重新自检”。
- **Q: 端口 8080 被占用了怎么办？**
  - A: 修改 `docker-compose.yml` 中的 `ports: ["8080:80"]` 为其他未占用端口，如 `["9090:80"]`。
